## What the pi original did

`@narumitw/pi-auto-thinking` automatically selected a reasoning level from the active model's thinking capability and a per-turn task-difficulty classification.

## The omp shape

The hook reads bounded facts for the latest projected user message, then asks `omp.agents.completion` for the ordered five-rung `minimal` → `xhigh` ladder with `role="smol"`. Its `default=` is a conservative deterministic heuristic derived from message size, structure, media, and complexity markers—not a permissive library default. This follows the classifier-hardening ruling: constrained choices use earliest-match resolution, and the caller must select the safe deterministic answer for timeout, transport failure, empty output, or an unmatched emission (`docs/py/12-agents.md`, “One-shot completions”; `docs/py/06-policy.md:2011-2023`).

Until the merged catalog gains an extension-visible reader, a non-`OFF` current `Effort` is the only positive capability evidence available to this extension. The selected level is therefore clamped no higher than the current level; `OFF` defers rather than guessing that reasoning is supported. The result is a `Modify(patch={"thinking": ...})` from the ordered `turn_start` transform. The long-flagged patchability ruling did land: frozen `TurnStartEvent.thinking` is `Effort` (`crates/py/python/omp/events.py:400-416`), and the mutable-field contract explicitly includes `turn_start.thinking` (`docs/py/05-hooks.md:1340-1346`). This fourth port closes the saga raised previously by plan-mode, profiles, and project-model-pin.

## Gaps

- **No extension-visible merged-catalog read exists for an arbitrary `ModelRef`.** Frozen `ModelRef` contains only `provider`, `api`, and `model` (`crates/py/python/omp/provider.py:1054-1060`). Frozen `ProviderHandle.models()` is reachable only from a handle for a provider declaration and returns `tuple[ModelSpec, ...]` (`crates/py/python/omp/provider.py:980-1023`), while the documented surface says `tuple[ModelCard, ...]` and promises resolved post-overlay cards (`docs/py/13-inference.md:363-378`); `ModelCard` is not frozen. The same document assigns merged updates to the reusable `WatchModels` cursor stream (`docs/py/13-inference.md:2146-2159`) but freezes no Python reader for it. Consequently this extension cannot inspect `ModelSpec.thinking` for a model it did not declare, so it conservatively uses current-effort evidence.
- **Paid classification and turn mutation have no legal common phase.** `omp.agents.completion` is documented as legal from REVIEW-phase hooks (`docs/py/12-agents.md:666-671`), but REVIEW may return only `Allow`, `Deny`, or `Defer`; `Modify` is TRANSFORM-only (`docs/py/05-hooks.md:699-705`). `turn_start` exposes `thinking` only as a mutable transform (`docs/py/05-hooks.md:1340-1346`), so this single bounded TRANSFORM hook expresses the intended port but would conflict with the documented paid-call phase rule. That rule was written for the per-invocation admission walk and does not compose with a turn-level classifier. The contract needs either paid completion in turn-event TRANSFORM or an explicit REVIEW-to-TRANSFORM handoff.
