## What this probes

There is no pi origin. This is a mechanical two-claimant conformance probe for collision rules that single-extension examples cannot exercise. `smoke()` uses fresh frozen `DeclarationRegistry` instances for each case, plus an isolated renderer key, so every refusal is repeatable without contaminating import-time declarations. Cross-extension winner selection belongs to the core registry; the frozen Python registry deliberately covers intra-extension claims only.

| Collision class | Documented resolution | Re-observed current result |
|---|---|---|
| Two device claimants, ordered precedence | The core registry chooses the highest-precedence live claimant, retains qualified shadows, and hides losers from `dyn`; frozen Python enforces intra-extension claims only | Conforms to the 2026-08-20 ruling: one frozen registry retains both local declarations, while separately configured registries deliberately have no merge/resolution operation |
| Two device claimants, equal precedence | Frozen Python raises `PrecedenceConflict` naming both claimant keys and the source package | Conforms: the message names `('tie_probe', 'family_a', 1)`, `('tie_probe', 'family_b', 1)`, and `publisher-a/extension-a` |
| Core name above `Precedence.CORE` | `DeviceNameError` at load | Conforms: `DeviceNameError` is raised before decoration |
| Two renderers for one `(name, family, rev)` | `DuplicateRenderer` at import, naming the incumbent holder and second claimant | Conforms: `DuplicateRenderer` subclasses `DuplicateRegistration` and names `_render_one` and `_render_two` |
| Two commands with one name | Core owns cross-extension arbitration; a frozen intra-extension duplicate raises `DuplicateRegistration(name, holder)` | Conforms: the local refusal names command `probe` and incumbent `precedence_conflict._handler`; separately hosted claimants remain outside this layer |
| Two shortcuts with one chord | A core incumbent is refused with `ShortcutError`; extension claimants resolve by manifest precedence and the loser is shadowed | **OPEN:** local duplication raises `DuplicateRegistration` naming `ctrl+alt+p` and incumbent `precedence_conflict._handler`; the frozen layer cannot exercise core incumbent or cross-extension arbitration |
| Two prompt contributions in one slot at equal priority | Additive; ties order deterministically by `(layer, publisher, extension_id)` | **OPEN:** both local contributions are accepted, but the frozen snapshot carries no layer/publisher identity with which to demonstrate the tie-break |
| Two providers with equal priority | Activation-time error names both declarations; provider id remains absent until one yields | **OPEN:** the second local registration immediately raises `DuplicateRegistration` naming the incumbent `ProviderDefinition`, while the first provider remains present |

## Closure records

1. **CLOSED — device arbitration is core-registry-owned by design.** The former finding treated the frozen registry's lack of cross-extension live-winner, qualified-shadow, and hidden-catalog resolution as a missing Python feature. The binding 2026-08-20 ruling assigns that arbitration to the core registry and says frozen Python holds one extension identity and enforces only intra-extension claims (`docs/py/01-devices.md:438-442`). Re-observation confirms the intended boundary: local ordered claims are retained, separate frozen registries do not meet, and no Python resolver is exposed.
2. **CLOSED — equal-device diagnostics now match the frozen contract.** The defect was an error shape that did not attribute both colliding keys and its source package, compounded by the probe's obsolete demand for `PrecedenceTie`. The fix in `crates/py/python/omp/_registry.py:558-572` raises public `PrecedenceConflict` with both keys and `source_package`, matching `docs/py/01-devices.md:413-415, 438-442`. Re-observation sees both `tie_probe` keys and `publisher-a/extension-a`; the assertion now requires that current shape.
3. **CLOSED — renderer refusal attributes both declarations.** The defect was a `DuplicateRenderer` payload containing only the renderer key. The fix makes it a `DuplicateRegistration` subclass with incumbent and claimant fields/messages and populates them from both registrations (`crates/py/python/omp/ui/__init__.py:88-95, 836-839`). Re-observation confirms the subclass relation and a refusal naming incumbent `_render_one` and second claimant `_render_two`.
4. **CLOSED — local command duplication names its incumbent.** The defect was a generic duplicate message containing only the command key. The fix derives the incumbent declaration holder and passes it to `DuplicateRegistration` (`crates/py/python/omp/_registry.py:1179-1189`, helper at `crates/py/python/omp/_registry.py:1578-1592`), satisfying the documented `DuplicateRegistration(name, holder)` contract (`docs/py/00-overview.md:981`). Re-observation sees both `probe` and incumbent `precedence_conflict._handler`; cross-extension arbitration remains outside the frozen layer rather than being simulated here.

## Still-open findings

5. **OPEN — shortcut collisions are not mechanically exercised at their owning layer.** Frozen local registration reports `DuplicateRegistration` with the normalized chord and incumbent handler (`crates/py/python/omp/_registry.py:1179-1189`). It cannot demonstrate either the core-incumbent `ShortcutError` or cross-extension manifest precedence and visible shadowed loser required by `docs/py/07-ui.md:1607-1610`.
6. **OPEN — prompt-slot tie ordering is not observable in the frozen snapshot.** The registry correctly accepts both additive contributions, but the local rows contain no `(layer, publisher, extension_id)` ordering identity. The probe therefore cannot mechanically demonstrate the deterministic equal-priority tie-break required by `docs/py/08-context.md:783-785`; it does not expect or request a duplicate refusal.
7. **OPEN — equal-priority providers still fail at the wrong phase and do not fail closed.** Frozen registration immediately raises `DuplicateRegistration` (now correctly naming the incumbent holder), and `provider_definitions()` still returns the first provider. The contract instead requires an activation-time error naming both `(publisher, extension_id, declaration_id)` values and an absent provider id until resolution (`docs/py/13-inference.md:280-282`).
