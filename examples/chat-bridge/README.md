# What the pi original did

`pi-lark-notify` bridged one coding session to Lark: it sent a completion notification when the main conversation settled, then polled replies to that notification and injected each reply back into the corresponding session. This port keeps the bidirectional behavior but treats the remote chat service as a generic authenticated webhook.

# The omp shape

`agent_end` is the OBSERVE event immediately after the `agent_settled` domain boundary, so the outbound path formats only bounded structural completion facts and never copies transcript content. The frozen HTTP surface currently forces that summary into a `summary=` query on `omp.env.http_get`; the body is capped at 1 KiB before URL encoding. Authentication is a two-minute `omp.creds.mint_scoped("webhook")` token rather than a setting or environment secret (`docs/py/05-hooks.md` §“Turn and submission lifecycle”, `docs/py/11-env.md` §“Open questions”, and `docs/py/13-inference.md` §“Credentials”).

The inbound cadence is one session-scoped `omp.agents.schedule` row using `Every`, `COALESCE`, `overlap="skip"`, and `Inject(visible=True)`. A schedule-origin `before_agent_start` TRANSFORM fetches at most 64 KiB, admits at most 16 replies, caps the injected batch at 4 KiB, and replaces the scheduled input with that batch; a REVIEW handler denies the empty sentinel so a no-reply poll never reaches the model or transcript. Reply ids are appended to typed `omp.state` at `StateScope.SESSION`; the fold rejects ids already seen in the session. There is no `asyncio` timer, task, loop, side file, or second source of truth (`docs/py/12-agents.md` §§“inject” and “Scheduling”; `docs/py/09-journal.md` §“omp.state”).

# Gaps

- Genuine webhook POST is absent. The required symbol is `omp.env.http_post(url, *, body: bytes, timeout: Duration | None = None, headers: Mapping[str, str] = ...) -> HttpResponse`; the frozen surface exports only `http_get` at `crates/py/python/omp/env.py:887-913,1147-1214`. `docs/py/11-env.md` §“Open questions”, lines 2205-2217, explicitly says no Environment-side HTTP client ships in v1. The example's query-GET is bounded and smokeable but is not a semantic substitute for a POST webhook.
- Even the available `omp.env.http_get` is a declaration that always raises `NotWiredError` at `crates/py/python/omp/env.py:905-913`; `docs/py/11-env.md` §“Open questions”, lines 2209-2211, documents that it remains unwired. Both bridge directions therefore need the scoped-egress frame before this port can run against a real endpoint.
- A durable schedule cannot identify or carry its work. `omp.agents.Inject` has only `mode` and `visible`, and `omp.agents.schedule` has no prompt or callback at `crates/py/python/omp/agents.py:818-833,923-936`; `BeforeAgentStartEvent` also has no `schedule_id` at `crates/py/python/omp/events.py:377-387`. This diverges from `docs/py/12-agents.md` §“Delivery targets”, lines 872-882, which says “the prompt goes to this agent.” The example can only recognize `InputSource.SCHEDULE`, so until `Inject(prompt=...)` or schedule provenance/callback delivery is frozen, its TRANSFORM cannot distinguish this poll from another extension's scheduled injection.
