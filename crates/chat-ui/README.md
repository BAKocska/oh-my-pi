# omp-chat-ui

`omp-chat-ui` is the host-agnostic designed chat scene shared by omp frontends. It owns the ordered block scheduler, bounded live presentations, composer attachments and completion, status chrome, viewport-local damage, and matching overlays. It does not own an agent, persistence, credentials, catalog, terminal, or synthetic demo data.

Every conversation item receives a monotonic `BlockOrdinal`. Streaming assistants and running tools remain live blocks whose scheduler-owned height allocation is clipped inside the fixed viewport. Finalization freezes an immutable semantic `Entry` snapshot and swaps the live presentation for it: the settled snapshot stays in the mutable viewport, reflowing at the current width and restyling with theme changes, until capacity pressure retires it. A later block may finish first, but it cannot retire across an earlier active block.

A host creates `Chat` with its `UiContext`, forwards input as `Intent` values, and applies `BackendEvent` values through `Chat::apply_backend_event` or the typed mutation methods. `Chat::render` returns an exactly viewport-sized `ViewportFrame`; painting it is history-neutral. On each normal-screen frame tick, the host asks `Chat::retirement_batch(viewport)` for the shortest contiguous finalized prefix that must retire for the live tail to fit the transcript capacity (nothing while the screen has room and fewer than 256 blocks are live), computes the post-acknowledgement viewport through `Chat::render_after_retirement`, passes both frames to `Renderer::retire`, and calls `Chat::mark_retired(&batch)` only after the terminal transaction succeeds. Graceful shutdown instead uses `Chat::flush_retirement_batch` until every eligible head is drained. A zero-height batch is valid when its ordinal range contains only dropped tombstones.

Renderer-controlled native scrollback changes only through explicit retirement, but terminal resize and teardown remain external physical effects. Viewport damage is merely a paint optimization and never implies that rows are stable, committed, or safe to scroll. Rewind and clear operations leave committed native rows immutable, tombstone affected uncommitted snapshots, append a finalized semantic marker, and preserve the logical retirement frontier.

Committed snapshots are retained so `Chat::begin_replay` can render the complete committed prefix through a separate replay cursor without changing block phases or rewinding the logical frontier. The terminal host uses this for settled width resizes per `ResizeScrollback`: `rebuild` (default) erases native scrollback through `Renderer::reset_history` before replay, `append` replays below the old-width copy, and `preserve` repaints only the viewport. `rebuild` degrades to `append` inside terminal multiplexers, where ED3 would wipe pane history irrecoverably. A replay requested under an alternate-screen overlay remains pending until the normal buffer returns.

The production terminal host is `omp-app`. Other frontends can share the same scene and snapshot formatter without inferring terminal history from presentation geometry.
