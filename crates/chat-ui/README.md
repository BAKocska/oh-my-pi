# omp-chat-ui

`omp-chat-ui` is the host-agnostic designed chat scene shared by omp frontends. It owns the ordered block scheduler, bounded live presentations, composer attachments and completion, status chrome, viewport-local damage, and matching overlays. It does not own an agent, persistence, credentials, catalog, terminal, or synthetic demo data.

Every conversation item receives a monotonic `BlockOrdinal` and permanently declares a `BlockMode`. Tools, notices, and other conservative producers are `Mutable`. Assistant and thinking streams declare `AppendOnly`. Assistant messages expose only complete closed Markdown chunks: open fences, paragraphs that a later setext line could restyle, wrapping-sensitive output, and the current partial tail remain viewport-owned. Thinking exposes no live prefix because sanitation, elapsed status, and collapsed/expanded presentation remain mutable; after finalization it exposes the exact rendered `ThinkingEntry` as one stable semantic chunk. Only the current logical head may naturally retire the next stable semantic row, and only under row pressure. The scheduler records the emitted prefix; final retirement writes only its remaining suffix, while a fully emitted finalized head advances without a terminal write. A later block may finish first, but it cannot emit or retire across an earlier unfinished block.

A host creates `Chat` with its `UiContext`, forwards input as `Intent` values, and applies `BackendEvent` values through `Chat::apply_backend_event` or the typed mutation methods. `Chat::render` returns an exactly viewport-sized `ViewportFrame`; painting it is history-neutral. On each normal-screen frame tick, the host asks `Chat::retirement_batch(viewport)` for a natural stable-head append or the shortest contiguous finalized prefix needed to restore capacity, computes the post-success viewport through `Chat::render_after_retirement`, and acknowledges with `Chat::mark_retired(&batch)` only after the terminal transaction succeeds. Zero-row append-only completion is acknowledged without calling the writer. Graceful shutdown uses `flush_retirement_batch` to drain every eligible finalized head. A writer failure is fail-stop: no acknowledgement, logical advance, or retry occurs.down instead uses `Chat::flush_retirement_batch` until every eligible head is drained. A zero-height batch is valid when its ordinal range contains only dropped tombstones.

Renderer-controlled native scrollback changes only through explicit retirement, but terminal resize and teardown remain external physical effects. Viewport damage is merely a paint optimization and never implies that rows are stable, committed, or safe to scroll. Rewind and clear operations leave committed native rows immutable, tombstone affected uncommitted snapshots, append a finalized semantic marker, and preserve the logical retirement frontier.

Committed snapshots are retained so `Chat::begin_replay` can prepare the complete committed prefix plus any emitted prefix of the active append-only head without changing block phases or rewinding the logical frontier. Replay is bottom-first: the history suffix that fits in leading blank viewport space is moved into the final viewport, the prefix remainder is retained, and `Renderer::replay_frames` serializes the segmented `remainder || final_viewport` in one synchronous writer call. `append` retains native history; `rebuild` includes the history reset in that same buffered transaction; `preserve` repaints only the viewport. `rebuild` degrades to `append` inside terminal multiplexers. A replay requested under an alternate-screen overlay remains pending until the normal buffer returns.

The production terminal host is `omp-app`. Other frontends can share the same scene and snapshot formatter without inferring terminal history from presentation geometry.
